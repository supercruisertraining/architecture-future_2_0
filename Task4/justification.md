# Обоснование конфигурации инфраструктуры

## Виртуальные машины

### API Gateway VM
- **Назначение**: Единственная публичная VM, принимает внешние запросы
- **Конфигурация**: 2 vCPU, 2GB RAM
- **Доступ**: Публичный IP, Security Group с открытыми портами 80/443/22
- **Экономия**: Preemptible instance для снижения стоимости

### Internal Services VM  
- **Назначение**: Основные бизнес-сервисы приложения
- **Конфигурация**: 4 vCPU, 8GB RAM
- **Безопасность**: Только приватная сеть, доступ через API Gateway

### AI Services VM
- **Назначение**: ML/AI обработка, требует больше ресурсов
- **Конфигурация**: 8 vCPU, 16GB RAM, 50GB disk
- **Оптимизация**: Увеличенные CPU/RAM для вычислений

### DB & RabbitMQ VM
- **Назначение**: База данных и брокер сообщений
- **Конфигурация**: 4 vCPU, 8GB RAM, 100GB disk
- **Надежность**: Non-preemptible, гарантированная работа
- **Диск**: Увеличенный размер для данных

### DWH Services VM
- **Назначение**: Аналитика и хранилище данных
- **Конфигурация**: 4 vCPU, 8GB RAM, 200GB disk
- **Хранилище**: Максимальный диск для аналитических данных

## Диски

### Boot Disks
- **Образ**: Ubuntu 22.04 LTS (стабильная версия)
- **Размеры**: От 20GB до 200GB в зависимости от назначения
- **Тип**: Network SSD для баланса цена/производительность

### Стратегия размера
- **Минимальный** (20GB): API Gateway, базовые сервисы
- **Средний** (50-100GB): AI, DB сервисы
- **Максимальный** (200GB): DWH для больших данных

## Настройки сети

### Архитектура безопасности

### Public Subnet (192.168.10.0/24)
- **Ресурсы**: Только API Gateway VM
- **Доступ**: NAT, публичный IP, ограниченные порты
- **Security Group**: HTTP/HTTPS/SSH извне

### Private Subnet (192.168.20.0/24)  
- **Ресурсы**: Все внутренние сервисы
- **Доступ**: Только из public subnet
- **Изоляция**: Нет прямого доступа из интернета

### Security Groups
- **api_gateway_sg**: Входящие 80/443/22, исходящие в private сеть
- **internal_sg**: Внутренний трафик между сервисами

## Причины использования декларативного подхода

### Повторяемость и надежность
- Идентичная инфраструктура в разных окружениях
- Идемпотентность - многократное применение безопасно

### Версионирование и контроль
- Git для отслеживания изменений инфраструктуры
- Code review для всех модификаций
- История изменений с комментариями

### Безопасность и соответствие
- Инфраструктура как код = документация
- Воспроизводимость аудитов
- Соответствие стандартам безопасности

### Автоматизация и CI/CD
- Интеграция с pipelines развертывания
- Автоматическое тестирование изменений
- Быстрое развертывание/удаление сред

### Коллаборация и знания
- Единый источник истины для команды
- Разделение обязанностей через переменные
- Быстрая адаптация новых членов команды
